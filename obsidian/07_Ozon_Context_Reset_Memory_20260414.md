## Что это

Это главная заметка для продолжения работы по Ozon после сброса контекста.

В рамках текущего чата работать только по Ozon.

## Неперезаписываемые правила пользователя

1. Не давать неточных ответов. Любую ключевую цифру по продажам, акциям, рекламе, остаткам и заказам сначала перепроверять по live-источнику или свежему отчету.
2. Не домысливать, если UI и API расходятся. Сначала фиксировать конфликт источников, потом принимать решение.
3. Не уходить в Wildberries, Yandex Market и другие маркетплейсы, если задача не требует прямого сравнения ради Ozon.
4. Убирать из акций все SKU, которые уходят ниже `min_price`.
5. Не включать автоакции и автодобавление в акции. Акции возвращать только вручную и только на SKU с экономикой.
6. Не подключать механики `отзывы за баллы`.
7. Правило пользователя по цене: поднимать стоимость всех товаров на `1%` ежедневно в обоих Ozon-магазинах в течение `14` дней. Перед каждым применением проверять текущие цены и ограничения кабинета.
8. Новые изображения и карточки строить на эталонных физических товарах. Нельзя менять форму изделия, геометрию пластины, застежку, тип ремешка и сам текст гравировки без явного основания.

## Ключевые рабочие выводы, которые нельзя потерять

1. Главная ошибка прошлого состояния была не в отсутствии ассортимента, а в распылении рекламы и внимания по хвосту.
2. Акции нельзя оценивать по ощущению. Сначала проверять `min_price`, участие в авто-слое, фактический буст и экономику.
3. Если API и UI расходятся, нельзя отключать кампанию вслепую.
4. Рабочий рост сидит на узком геро-ядре, а не на всем каталоге.
5. Слабый SKU сначала лечится первой галереей, отзывами, доверием и точностью интента, а не только ставкой или скидкой.
6. Дубли, остаточные warning и SPU-конфликты на Ozon часто живут дольше, чем фактический дубль. Нужна повторная live-проверка перед каждым жестким действием.
7. Любое решение по промо-слою должно быть совместимо с правилом пользователя: не опускаться ниже `min_price`.

## Что делать перед любым новым действием по Ozon

1. Убедиться, что задача относится к Ozon, а не к другому маркетплейсу.
2. Проверить кабинет: `3292967` или `311191`.
3. Проверить, есть ли свежий live-report по нужной зоне: цена, акции, реклама, остатки, ошибки.
4. Если свежего среза нет, сначала снять новый срез, потом отвечать или применять правки.
5. Если задача касается акций, первым делом проверить `min_price` и флаг автодобавления.
6. Если задача касается рекламы, сначала сверить API и Seller UI, особенно по кампаниям с конфликтной атрибуцией.
